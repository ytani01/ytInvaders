## きっかけ

利用者から「スマホでは移動をレバーのようにしたい。左に左右移動のレバー、右に FIRE。
操作しやすいように操作欄をもっと高く」と依頼があった。
それまでは画面下に ◀ FIRE ▶ の 3 つのボタンが並び、高さは 5.5rem だった。

## やったこと

- 操作欄を左半分のレバーと右半分の FIRE にし、◀ ▶ ボタンを無くした（`src/pages/index.astro`）
- レバーは中心と左右の端を固定にした。触っている位置の中心からの距離で速さが決まり、
  つまみが欄の端に着く所で全速（今までの最高速 260）になる。中心から半径の 15% までは動かない。
  つまみは触っている位置へ動き、離すと真ん中へ戻る
- 倒し量の換算を `leverAxis` として `src/game/game.ts` の純粋な関数に切り出し、
  `tests/logic.test.ts` にテストを 2 つ足した。自機の移動はキーの左右と倒し量を足して ±1 に収める。
  キーだけのときは前と同じ -1 / 0 / 1
- レバーは 1 本の指だけを追う。離したとき・pointercancel・フォーカスが外れたときに倒し量を 0 に戻す。
  FIRE とは別の指で同時に押せる
- 操作欄の高さを `min(25dvh, 12rem)` + safe-area にした
- FIRE にしか使わなくなった `bindHold` を `bindFire` にした
- README の操作の表を直した

着手後に、reviewer の指摘を受けて 2 点を決め直した（利用者が決めた）。

- 最初は「触った所が中心」にしたが、左端の近くを触ると指が画面の外へ出られず、
  左へ全速で動かせない（幅 390px でレバーの左約 1/3）。レバー全体を固定にした
- タッチ画面付きの PC でも操作欄が出るので、高さに 12rem の上限を付けた。
  スマホの縦向き（高さ 844px）でも上限が効き、画面の約 23% になる

## 確かめたこと

verifier が `npm run preview` で、CDP の `Input.dispatchTouchEvent` でタッチ操作して測った
（[archives/agents/TODO-005/verifier-report.md](../agents/TODO-005/verifier-report.md)）。

- 操作欄の高さ: 390x844 と 1920x1080（タッチ有り）で 192px、667x375 で 93.75px。
  タッチ無しの 1280x800 では出ない。レバーと FIRE は左右半分ずつ
- 速さ（px/秒）: 中心 0、右へ半径の 50% で 106（期待 107）、左へ半径ちょうどと欄の左端ぎりぎりで -260。
  右へ半径ちょうどは 246 で、自機が画面の右端に着いて止まった分が平均に入ったと見られる
- 指を離すと止まる（0.3 秒で動き 0）。レバーを押したまま別の指で FIRE を押すと、弾が出て自機も動き続ける
- 全速のとき、つまみは欄の中に収まる（390x844 で欄 8..185 に対してつまみ 109..181）。
  横向きでも ◀ ▶ とつまみは切れない。スクリーンショットで欠けや余計なものが無いことを見た
- `npm test` は 16 件 pass、`npm run build` も通る

## 分担の振り返り

- reviewer（1 回目）: 左端の近くでは左へ全速が出ないこと、タッチ PC で操作欄が大きくなりすぎることを見つけた。
  どちらも利用者が仕様を決め直すきっかけになった。2 回目は、全速のときにつまみが欄から切れることを見つけた
- verifier: 仕様との食い違いは見つからなかった。自機の位置の取り方で一度つまずき
  （自機と同じ色の敵を拾った）、canvas の画素から取るやり方に直している
- 見込みとの差: reviewer が 2 回になった。1 回目の指摘で仕様が変わったため
- 次に入力の方式を決める項目では、項目を立てるときに「画面の端の近くを触ったとき」
  「タッチ画面付き PC」を利用者に先に聞く。reviewer に見つけさせるより 1 往復少なく済む。
  verifier には、自機の位置の取り方（canvas の画素の 1 行を見る）と Playwright の置き場所を
  依頼に書いておけば、つまずきの分を減らせる
