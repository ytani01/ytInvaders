## きっかけ

利用者から「スペースを押しても反応しないときがある」と報告があった。

## やったこと

原因は 2 つだった。

- Space は押している間だけ `input.fire` が true になる作りで、押して離すまでが
  1 フレームより短いと、ゲームの更新が見る前に false に戻っていた
- 撃ってから 0.35 秒と、自機の弾 2 発の上限の間に押しても何も残らなかった

`src/game/game.ts` に `fireQueued` を足した。Space の keydown（`ev.repeat` は除く）と
FIRE ボタンの pointerdown で true にし、撃てるようになった時点で 1 発出して false に戻す。
`update()` の先頭で `mode !== 'playing'` のときに捨てるので、一時停止・タイトル・
ゲームオーバー・フォーカスが外れたときの押下は残らない。間隔と上限、押しっぱなしの連射は変えていない。

あわせて `package-lock.json` の `engines` を `package.json`（TODO-001 で `>=22.18.0`）に揃えた
（npm が書き換えたもの）。

## 確かめたこと

- 直す前: `keyboard.press('Space')` で 20 回中 4〜8 回しか弾が出なかった
- 直した後（自機の弾の `fillRect` をページの中で記録して数えた）:
  - すぐ離す押下 5/5、FIRE のタップ 5/5 で発射
  - 0.5 秒の押しっぱなしで 3 回とも 2 発、間隔 347〜350ms
  - 撃てない間に 3 回押しても 3 回とも 2 発（覚えるのは 1 回分）
  - 一時停止中・タイトル・blur の後の押下で、再開・開始したときに撃たない（各 0/10）
- `npm test` 14 件 pass、`npm run build` 成功
- reviewer: 直すべき・直すとよい 0 件、参考 4 件

## 残ること

- 1 発目の直後に押した 2 発目の時刻差を測ったとき、3 回中 1 回だけ 2 発目が記録されなかった。
  同じ経路は「撃てない間に 3 回押す」で 3/3 通っているので、計測の揺れと見て追っていない
- 覚えた押下を捨てるのは次の `update()` なので、1 フレーム未満の間に一時停止と再開が
  両方起きると 1 発残る（reviewer の参考 1）。起きても 1 発出るだけなので直していない

## 分担の振り返り

- **reviewer** は差分の分岐に問題は無いとしたうえで、直す前の計測の帯にシールドが
  入っていることと、測定 3 が 2 つの原因を混ぜていることを指摘し、直した後に見るべき
  7 点を挙げた。これが verifier の 2 回目の依頼の元になった
- **verifier** は 1 回目で症状を再現した。2 回目は画素を Node から 16ms おきに見張る
  やり方で、この機械（Raspberry Pi）では間に合わず、値が揺れて判定できなかった
  （16 分、回数は 10〜20 回ずつ）。3 回目で `fillRect` を包んでページの中で記録する
  やり方に変え、4 分半で判定できた
- 見込みとの食い違い: 担当の組み方は見込みどおり。verifier が 3 回に割れたのは、
  管理者が測り方（画素の見張り）と回数（10〜20 回）を依頼に書いたせいで、
  最初から描画の呼び出しを記録させていれば 1 回で済んだ
- 次に Canvas のゲームで挙動を測るなら: 画素ではなく描画の呼び出し（`fillRect` など）を
  `addInitScript` で包んでページの中で記録させる、と依頼に書く。回数は条件式で決まる
  挙動なら 3 回、確率で起きる不具合なら直す前の失敗率から逆算して書く
