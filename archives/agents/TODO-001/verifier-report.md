### localStorage が使えないとき

`addInitScript` で `window.localStorage` の getter が例外を投げるようにして開き、
Enter で開始して 2 秒動かした。pageerror は 0 件で、スクリーンショットも
タイトルが正常に消えてプレイ画面になっていた。**ただしこれは `loadHigh`（読み込み、
モジュール初期化時）の経路しか通していない。** `saveHigh` はゲームオーバー時に
呼ばれるが、今回の実測ではゲームオーバーまで到達させていない（残機を 3 回
減らすのに時間がかかるため、効率を優先して省いた）。`saveHigh` 側の
try/catch が実際に効くかどうかは確かめられていない。

2. **一時停止中に自機が見えないコマがあったこと**。無敵点滅の仕様どおりの

## 追加の実測（← の移動量だけ）

管理者からの指示で、← の移動量だけを測り直した。新しいページで Enter 直後（被弾する前）に
← を 0.5 秒、続けて同じページで → 0.5 秒・← 0.5 秒をもう 1 回ずつ。各回の前後で
`#hud-lives`（DOM）の表示と、自機の重心 x（`584-602` の帯、canvas の実ピクセルから算出）を
記録した。スクリプトは `archives/agents/TODO-001/verify.mjs` に `leftRecheck()` を足し、
`node verify.mjs --left-recheck` で単独実行できるようにした（既存の関数・実行内容は変えていない）。

| 回 | 操作 | LIVES（前→後） | 重心 x（前→後） | 差分 | 被弾 |
|---|---|---|---|---|---|
| 1 | ← 0.5 秒 | 3 → 3 | 239.48 → 120.65 | -118.83 | なし |
| 2 | → 0.5 秒 | 3 → 3 | 120.65 → 234.33 | +113.68 | なし |
| 3 | ← 0.5 秒 | 3 → 3 | 234.33 → 116.67 | -117.65 | なし |

console error・pageerror ともに 0 件。

3 回とも被弾は無く、← と → の移動量はほぼ対称（-118.83 / +113.68 / -117.65px、
`PLAYER_SPEED=260px/s` から期待される 130px よりやや小さいが、3 回とも同程度）で、
前回報告した「← だけ極端に小さい（-52.9px）」という食い違いは再現しなかった。
前回はこの区間で LIVES が 3→2 に変わっており（実測ログに記録済み）、
「確かめられなかったこと 1」に書いた被弾時の画面の揺れによる測定への混入という
推測を裏付ける結果になった。**ただし今回も被弾していない場合の値が期待値 130px より
やや小さい（113–119px）ことは残っており、これが測定方法の誤差（帯の範囲、
フレームの端数、`waitForTimeout` の余分な待ち時間）によるものか、実際の移動量の
問題かは切り分けていない。**
