## 対象範囲（作る・変えるファイル）

- `package.json` — `"test"` スクリプトを足す。**依存関係は足さない**

これ以外のファイルは変えない（`TODO.md` と `archives/` も触らない）。

## 保つもの

- ゲームエンジン・描画ライブラリ・テストフレームワークを入れない。Canvas 2D と WebAudio だけ
- 見た目はネオン調のベクター図形（ドット絵にしない）。`shadowBlur` のグロー、
  撃破時のパーティクル、被弾時の画面の揺れ、流れる星空の背景
- 敵は横に動き、端で 1 段下がって向きを変える。数が減るほど速くなる
- 操作: ←→ / A D で移動、Space で射撃、P で一時停止、Enter で開始。
  タッチは画面下の左右ボタンと射撃ボタン。ゲームパッドは入れない
- ハイスコアは localStorage。**読み書きは try/catch で囲み、使えないときもゲームは動く**
- AudioContext はユーザー操作（キー・タッチ）の後に作る／resume する。使えなくても落ちない

## 設計の指示

- 当たり判定と編隊の 1 ステップの更新は、DOM・Canvas に触らない純粋な関数として
  書き、`node --test` から import できるようにする。モジュールの読み込み時に
  `window` / `document` に触らないこと（触るならそれを別ファイルに分ける。
  ファイルは増やしすぎない）
- Node 26 は `.ts` を型を落として直接実行できる。`npm test` は
  `node --test tests/` 相当で、ビルド手順を挟まない。import は `.ts` 拡張子付きで書く
  （型だけの import は `import type`。enum や namespace など型を落とすだけで
  動かない構文は使わない）。`astro check` 相当で型エラーが出ないようにする
- 時間の刻みは `requestAnimationFrame` の dt を使い、タブ復帰で dt が大きく
  なっても弾が敵をすり抜けないよう上限を付ける
- 画面サイズは論理解像度を固定して拡大縮小する（スマホ幅でも横スクロールが出ない）
