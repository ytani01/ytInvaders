### 1. 参考 — src/game/game.ts:353-356, 746-749（捨てる処理が「次の update が paused で走ること」に頼っている）

覚えた押下を捨てるのは `update()` の先頭（mode !== 'playing'）だけ。`suspend()`・`togglePause()`・
`newGame()` では捨てていない。update は mode によらず 1/120 秒ごとに走るので、ふつうは
一時停止・タイトル・ゲームオーバーのうちに捨てられ、前提は成り立つ。
抜けるのは、覚えてから次の update までの間（1 フレーム未満）に一時停止と再開が両方起きたときだけ。
例: 撃てない間に Space → 同じフレームのうちに P を 2 回、または Space の直後に Enter で再開。
タブが隠れると rAF が止まるが、戻った最初の update は paused で走り、そこで捨てられる。
実害は未確認で、ほぼ起きない。`suspend()` と `togglePause()` の中でも false にすれば、
タイミングに頼らなくなる（境界線上の判断なので報告だけ）。

### 2. 参考 — src/game/game.ts:263（ウェーブが変わっても覚えた押下は残る）

フォーカスが外れたとき）にウェーブの変わり目は入っていないので、仕様どおり。気になるかどうかの

### 3. 参考 — src/game/game.ts:714（`ev.repeat` の扱い）

OS のキーリピートは `ev.repeat` が true なので覚えず、`input.fire = true` だけ付け直す。
押しっぱなしでは最初の keydown で覚えた分が最初の 1 発で消え、その後は前と同じく
`input.fire` と cooldown で撃ち続ける（連射の間隔は変わらない）。
キーリピートを keyup + keydown（repeat が false）の組で送る環境があると、離した後に 1 発余計に
出る可能性がある。古い Linux の Firefox にあった挙動で、今の環境で起きるかは未確認。

## 問題なかった観点

- 捨てる箇所: タイトル・一時停止・ゲームオーバー（やり直しを受け付けない 1 秒も含む）・blur / visibilitychange は、どれも mode が playing 以外になり、次の update で捨てられる（指摘 1 のまれな場合を除く）
- 押しっぱなしの連射: 条件は `input.fire || fireQueued` で、`input.fire` 側は前と同じ。覚えた分は撃ったときに消えるので、連射が 1 発増えることは無い
- FIRE ボタンで開始・再開: `startOrContinue()` の後に覚えるので、playing になったときだけ残り、最初の update で 1 発出る。前は押している間に update が走れば出ていた。今はすぐ離しても必ず出る。許容済みの「1 発撃つ」の範囲。ゲームオーバー直後の受け付けない間に押した分は、mode が gameover のままなので捨てられる
- 撃てない間の押下を 1 回分だけ覚える: 真偽値なので、何回押しても 1 発にまとまる。間隔（`FIRE_COOLDOWN`）と 2 発の上限は変わっていない
- canvas のタップと Enter での再開は `fireQueued` に触れないので、撃たない
- コメントは「なぜ」を書いている。変更は依頼の範囲だけ
